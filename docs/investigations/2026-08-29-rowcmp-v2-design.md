## 3. ★駆動を要らなくする回避策 (先に検証する)

飽和窓 F150..F400 は、**段差を保ったまま鎖が静止した状態**である。
アンカーは静止しており、並進不変性から **「アンカーが原点にある静置」と物理的に同じ**はず。

→ **`restosc NETDUMP=1` (駆動なしの静置) の `d̄_sat` が、駆動版の飽和窓の `d̄_sat` と一致するか**
を先に確かめる (番人 W1)。一致すれば **N1 は不要**になり、既存ツールだけで v2 が回る。

- 一致の基準: **両側 (A/B)・両条件 (flat/ladder)・全 Joint で ±10%**。
- `restosc` の起動: `MMD_TEST_PMX=<probe> NETDUMP=1 STRAND=R SUBSTEPS=1 ITERS=10 NOCONTACT=1 OUTDIR=<dir>`
  (`STRAND` の既定は `髪BR` なので、本プローブでは **`R` を明示**する)。
### ★3-b. W1 が FAIL したときの読み方 — **両様に読む** (改訂3)

FAIL を「N1 が要る」という**手続き上の読み**だけで処理しない。**物理上の読みを先に置く**:

- 接触なし・純並進駆動なので、**並進不変性は成り立つはず**である。
  それでも静置と飽和窓が割れるなら、**経路依存 (履歴依存) の兆候**である。
- 履歴を持つ機構は **warm-start** であり、これは **V0 と噛み合う**。
- → **W1 の結果自体が V0 の最初の証拠になりうる。**

**取り決め**: W1 が FAIL しても**すぐ N1 (計装追加) へ走らない。**
1. まず **V0 の観点で読む** (どちら側が割れたか。warm を持つ A 側だけが割れるなら V0 の傍証)。
2. その読みを記録したうえで、**N1 の要否を報告して止まる。**

## 4. 事前登録の仮説と「出るはずの指紋」

> ★**注記 (タスク21〜22 との整合)**: 過去の行レベル等価実証は
> **「両側まっさらから開始」** の条件で行った。warm の履歴が積まれていない状態なので、
> **当時 warm 差が見えていないのは矛盾ではない。** v2 は**走行中の窓**を見るので、
> そこで初めて非対称が現れる。

### V0 — **warm-start の非対称** ★最重要 (改訂1)

**根拠 (どちらも既に確定している事実):**

- **Bullet 2.75 はジョイント行を warm-start する** (2026-08-09 に実ソースで確認)。
- **当エンジンのジョイント warm-start は 2026-08-12 に意図的に撤去され既定 OFF**
  (`PhysicsWorld.UseJointWarmStart(Angular)` = false)。静止スレッドのタスク14 で再導入も却下済み。
- よって**飽和窓 (走行中の窓) では「bulletref 非ゼロ / 当エンジン ゼロ」の非対称が期待値**であり、
  **§V3 に書いた「iter=0 の appliedImpulse が両側 0」という前提はおそらく崩れる。**

**なぜ主因になりうるか**: warm が効くと**複数フレームをかけて厳密解へ漸近**するので
掃引順序の跡が薄れる。warm が無いと**毎フレーム 10 反復でゼロから解く**ので
**順序依存の配分が残る**。→ **V1 (求解順) と同じ flat の逆転を、別機構で説明できる。**
H2'' (励起が入っていない) の候補リストとも整合する。

**期待する指紋**
- `rowtrace` の `iter=0` で **`appliedImpulse` が bulletref 非ゼロ・当エンジン ゼロ**。
- かつ bulletref 側のその値が、**飽和窓では前フレームの解に漸近**していること
  (フレームをまたいで同じ値に落ち着く = 履歴が効いている証拠)。

**否定条件**
- **bulletref 側も `iter=0` で 0** → V0 棄却。
- 非対称は在るが、**残差配分の逆転と定量的に対応しない**
  (例: 非対称の大きさが flat/ladder で同程度なのに逆転は flat だけ)
  → **「存在するが主因ではない」**と記録し、V1/V2/V3 へ進む。

**★列の意味を先に確定する (符号規約と同じ作法)**
`rowtrace` の `appliedImpulse` が **warm 込みの累積**なのか **反復ごとの増分**なのかは、
**実データで先に確かめる**。確かめ方:
- 同一 `(frame,substep,joint,dof)` で `iter` を通して `appliedImpulse` が
  **単調に積み上がる**なら累積、**毎 iter で 0 付近に戻る**なら増分。
- `dImpulse` との関係 (`appliedImpulse[iter] - appliedImpulse[iter-1] == dImpulse[iter]` か) でも判る。

**どちらでも V0 は判定できる**:
- **累積**なら `iter=0` の値がそのまま「前フレームから持ち越した力積」。
- **増分**なら `iter=0` の `appliedImpulse` は 0 になりうるので、代わりに
  **`relVelBefore`(iter=0)** を見る。warm があれば**行を解く前に既に相対速度が消えかけている**。
  さらに `lower`/`upper` に対する初期位置でも読める。
**どちらの読み方を採ったかを結果に必ず明記する。**

### V1 — **行を解く順序の差** (flat の分布逆転の第一容疑)

Gauss-Seidel では **最後に解いた行がその瞬間ほぼ満たされる**ので、
掃引の順序が残差の配分をそのまま決める。

**V1-a 指紋 (順序が読める場合)**
- 同一 `(frame,substep,iter)` の (joint,dof) 列が A/B で**異なる**。
- かつ **「掃引の末尾に近い Joint ほど `err` が小さい」**関係が両側で成り立ち、
  **その順序が逆** (A が J0→J1→J2、B が J2→J1→J0 など)。
- **flat で残差の大小が逆転しているのに ladder では逆転しない**ことも説明できること
  (質量比が入ると別の項が支配するため)。

**V1-b 指紋 (順序が読めない場合の代替)**
- 反復 1 回目終了時点の `err` の Joint 別プロファイルを比べる。
  順序が違えば **iter=0 の直後に既に逆向きのプロファイル**が出る。
- `dImpulse` の Joint 別の大きさが、iter=0 で A/B 逆順に並ぶ。

**否定条件**: (joint,dof) の列が A/B で完全一致 → V1 は棄却。

### V2 — **アンカー (無限質量) 行の扱いの差**

J0 は `R0` (mode0・`invMass=0`) と `R1` を繋ぐ。**無限質量側の扱いは実装差が出やすい**
(実効質量、梃子腕、行の生成、リミットの上下限)。当エンジンには
`LinearLeverMode` / `LeverArmGate` / `MaxCorrectionVel` という **Bullet に無い概念**がある。

**指紋**
- `effMass` の A/B 比が **J0 の行だけ 1 でなく、J1/J2 は 1**。
- `lower`/`upper` (行の力積上限) が **J0 だけ違う** (当エンジンは `LockedRowImpulseBound`)。
- `axisX..Z` (行の軸) が J0 だけずれる → 梃子腕の取り方の差。
- **flat で J0 の残差が 5.9 倍**という観測と、J0 に限定した差が対応すること。

**否定条件**: J0 の `effMass` / `lower` / `upper` / 軸が A/B で一致 → V2 は棄却。

### V3 — **反復内の収束経路の差**

順序も実効質量も同じだが、**反復を重ねたときの進み方が違う**。

**指紋**
- **★`iter=0` の `appliedImpulse` の両側比較は「前提チェック」ではなく V0 の判定そのものとして読む** (改訂1)。
  ここが崩れても**計装故障ではない**。崩れることが期待値である。V0 の節を参照。そのうえで、
- `iter` に対する `err` の減り方の**形**が違う (単調 vs 振動、片側だけ `clamped` が立つ、など)。
- `relVelBefore`/`relVelAfter` の差 (= その行が実際に消した相対速度) の累積が A/B でずれる。
- 2026-08-22 の静止での所見 (**行構築時の相対速度 / 目標速度 = 自前 0.327 / Bullet 0.000409**)
  と同じ構図が、この系でも出るか。**出れば V3 の有力な裏取り**になる。

**否定条件**: 反復ごとの `err` 列が A/B で数値一致 → V3 は棄却 (差は行の外にある)。

| **R6** | 番人が落ちる | 判定不能。数値を出さずに報告して止まる | — |

境界は「A/B の一致/不一致」で決まる質的判定なので、**数値の閾値は置かない**
(置くと後から動かせてしまう)。許容は **1 本だけ**を事前に固定する。

> ### ★改訂2 — 許容の扱いは **(b) を採用** (実測前に確定)
> **`1e-6` 相対という許容は維持する。** そのうえで判定に 1 行を足す:
>
> **「`1e-6` 〜 `1e-5` 帯の不一致は、既知の float ノイズ帯として別分類とし、指紋とはみなさない。」**
>
> 根拠: タスク22 の行レベル等価実証で、**10反復 × 16行の累積インパルスの最大相対差が
> `1.25e-5`** だった実測がある。`1e-6` は既知のノイズ床より厳しい。
>
> **なぜ (a) 単純な `1e-5` 化ではなく (b) か**: `1e-6` を残せば
> **「完全一致」「既知ノイズ帯」「本物の差」の3つに分けられる**が、
> `1e-5` へ緩めると前2者が潰れて情報が減るため。
>
> 分類: `< 1e-6` = **一致** / `1e-6〜1e-5` = **既知ノイズ帯 (指紋ではない)** / `> 1e-5` = **不一致**。

## 7. 「どの指紋も出ない場合」の記録形式 (事前登録)

```
[V1] (joint,dof) 列の A/B 比較        … 一致 / 不一致 (不一致なら列を全部転記)
[V2] J0 行の effMass / lower / upper / 軸  … A/B の値と比を全転記
[V3] iter ごとの err / dImpulse / clamped … A/B を並べて全転記 (flat J0 と J2 は必須)
[残差の出どころ] 行レベルが全て一致するなら、差は **行の外** にある:
     ・積分 (速度→位置の更新式・減衰の掛け方・サブステップ間の状態引き継ぎ)
     ・行を作る前の状態 (重力適用の順序、キネマ体の姿勢更新のタイミング)
     ・行の集合そのもの (どちらかにだけ在る行 / 無い行)
     → この3つのどれかへ次の設計を向ける、と明記して止まる
[結論]  「行レベルでは差が説明できない」= それ自体が強い所見。撤回ではなく前進として記録する
```

★**「差が見つからない」で終わらせない。** 行が全部一致するなら、
**差は行の外にしか在り得ない**ので、探索範囲がむしろ狭まる。そう書いて次へ渡す。

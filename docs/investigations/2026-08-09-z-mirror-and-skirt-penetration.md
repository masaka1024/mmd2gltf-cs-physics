# 報告用DATA — Z鏡像修正の結果 と スカート貫入（2026-08-09）

## 1. 今回の修正（確定・完了）
- **真因**: Unity境界（`MmdPhysicsBehaviour` / `BonePoseCsvPlayer`）の座標変換が「対を持たない3回目のZ反転＝鏡映(det−1)」を掛けていた。
  - メッシュ経路: PMX →(mmd2gltf ReverseZ)→ glTF →(UniGLTF ReverseZ, 既定Z)→ Unityボーン。**二重ReverseZが相殺しUnityボーン＝PMXネイティブ座標値**。
  - 物理剛体: `GlbPhysicsReader` が raw PMX で構築（反転なし）。
  - なのにブリッジが `pos=(x,y,-z)`, `rot=(-x,-y,z,w)` を掛けていた＝鏡映。
- **確定根拠（Unity実測 DumpZ, 配置非依存）**: X-Z平面の掌性（符号付き面積）が **PMX=+1.583 / U2M=−1.583**（符号反転・絶対値一致）＝鏡映。並進・回転では符号は変わらないので決定的。
  - ModelRoot は `pos=(-0.031,0,0.491) euler=(0,343.9=−16.1°Y,0) scale=1`（シーン配置）。真の等長変換なら物理が正しく追従するため修正には無関係。
- **修正**: 上記4関数＋viz3関数のZ反転除去→単位スケールのみの等長変換（commit `9e90801`、両リポジトリ同期）。
- **結果**: **正面反転が消失（ユーザ実機確認）**。ヘッドレス回帰はビット不変（物理出力hash `84c0846c` 一致、main の stepMax 差は壁時計ジッタのみ）。

## 2. 汚染範囲（重要）
| 経路 | 鏡像の影響 | 調整データの有効性 |
|---|---|---|
| **Unityブリッジ**（MmdPhysicsBehaviour/BonePoseCsvPlayer） | **あり（鏡映）** | Unity目視での判断は汚染 |
| **ヘッドレス**（PmxReader直＋PhysicsWorld: restsim/hairfid/chainbug/main） | **なし（元からPMXネイティブ）** | 数値ベースの調整は有効 |

→ warm-start 0.85 / 接触パラメータ / 「7.95は仕様」/ 貫入計測 等は**ヘッドレスで実施＝フレーム正しく有効**。
一方「Unityで見て調整した」ものは鏡像汚染の可能性があり要再確認。

## 3. スカート貫入データ（すべて鏡像なしフレーム）

### 3-1. 静止（restsim, bind＋重力のみ）＝軽微
```
skirt(dyn box)=36 legs(capsule)=10
[bind/0step] peak skirt×leg 貫入 = 0.0646
[after 180steps] run-peak=0.2276  final-peak=0.0546 (スカート_1_2×左太もも)
貫通疑い(pen>0.170) 0/36 ・ 脚カプセル内部(INSIDE) 0/36 ・ 反対側へFLIP 0/36
最大落下 0.069
```
→ **静止では貫通なし。軽微。**

### 3-2. 駆動（hairfid, MMDベイクCSVで体を動かす）＝真の問題が顕在
```
自前 深貫入>0.5: 17,407イベント (ユニークフレーム5746, ユニークペア61)  最大=1.070
MMD 深貫入>0.5(幾何, 同分母): 67イベント  最大=1.182
→ 自前 >> MMD = 自前固有の衝突抜け
最大ペア: スカート_0_4×左太もも 1.070 / スカート_1_4×左太もも 1.028 / スカート_0_3×左太もも 0.939 ...
```
**接触は検出できている**のに止まらない:
```
例) スカート_0_4×左太もも pen=1.070 AABB=重なり 点=2(マニフォールド2点) ni=240.8(法線力積) 継続=37フレーム
マニフォールド点数分布(深貫入時): 点2=17,380 が支配（単点ではなく2点でも止まらない）
```
→ 診断: **接触検出・押し返し(ni 240〜352)はしているが、ジョイント拘束に負けて貫入が1.0+のまま数十〜数百フレーム継続**（綱引き負け）。

## 4. 解釈
- **スカート貫入は鏡像とは別問題**で、ヘッドレス駆動では**元から常に再現していた実問題**（MMD67に対し自前17,407）。
- Unityでは鏡像がスカートを反対側へ置いていたため、脚との貫入が違って見えていた（隠れる/別の形）。鏡像修正で**正しい側に来た結果、真の貫入が顕在化**。
- = 今回の修正が新たに壊したのではなく、**真の挙動が見えるようになった**。静止は軽微、駆動（脚が動く）で顕在化する。

## 5. 次の候補（以前「鏡像でないので不要」としたが、真問題として再検討対象）
1. **最大4点の永続マニフォールド**（Bullet btPersistentManifold 同等）: 現状 点2 でも止まらない→接触の多点安定化。
   - 実装前提（前回合意）: Bullet 2.75実ソースで MANIFOLD_CACHE_SIZE/getCacheEntry一致判定/sortCachedPoints/refreshの破棄条件/appliedImpulse引継ぎを確認してから。A/Bフラグ既定OFFでビット一致後にON計測。
2. **接触をジョイントに勝たせる**: 求解順（接触先→ジョイント後 or 反復配分）、split-impulse、接触の反復重み。
3. 計測指標（前回合意）: 深貫入件数(自前17407/MMD67が目標)、最大貫入、継続フレーム分布、マニフォールド点数分布、スカート統計、不変条件、step時間。

## 6. 再検討が必要な過去の結論（鏡像修正を踏まえて）
- **Unity目視ベースの判断**: 鏡像汚染の可能性→要再確認。
- **ヘッドレス数値ベースの判断**（7.95仕様 / warm-start 0.85 / 貫入17407 vs 67 / 髪は静止で正常垂下）: **フレーム正しく有効**。
- スカート貫入対策（4点マニフォールド等）は、鏡像に隠れていた真問題への対処として**今こそ着手する意味がある**。

## 7. 【追記】スカート貫入の根本原因＝接触とジョイントの綱引き（確定）

### 指摘の反映（診断の向き修正）
- 最大貫入は **自前1.070 < MMD1.182**。深さ1.0まで沈むこと自体はMMDでも起きる**正常挙動**。
  違いは**深さでなく頻度と継続**（MMDは一瞬で戻る、自前は数十フレーム沈みっぱなし）。
  → 診断は「押し返せない」ではなく「**押し返しが毎ステップ打ち消される**」。

### (1) 接触行のクランプ: 無し（コード確認）
- `SolveContacts`: `NormalImpulse = Math.Max(0, old+dPn)` の**非負クランプのみ**、上限・速度クランプなし。
- `NormalBias = Max(BaumgarteFactor(0.2)*pen/dt, restBias)` にクランプなし。

### (2) Bullet 2.75/2.83 setupContactConstraint（実ソース引用）
```c
btScalar positionalError = -penetration * erp/infoGlobal.m_timeStep;
btScalar penetrationImpulse = positionalError*solverConstraint.m_jacDiagABInv;
// erp = m_erp2 (split時) or m_erp。 "No explicit max error reduction cap exists in this code."
// 接触インパルスは m_lowerLimit=0 の非負クランプのみ(上限なし)
```
→ **Bulletにも接触クランプは無い＝我々と一致**。クランプ説は両面で否定。

### (3) per-step 実効回復速度（静区間・deep・同ペア, hairfid駆動）
| 条件 | 深貫入イベント | 1step Δpen平均 | 実効回復 | 実効/理論 |
|---|---|---|---|---|
| ベースライン | 17,407 | −0.011 | 0.33 u/s | **8%** |
| 角度だけ自由 | 11,651 | −0.005 | 0.14 u/s | 4% |
| **角度+並進 自由(接触+重力のみ)** | **285** | −0.057 | 1.69 u/s | **51%** |
| SPLIT=1(接触を擬似速度側) | 5,024 | −0.021 | 0.64 u/s | 18% |
| MMD(参考,幾何) | 67 | — | — | — |

### (4) 決定的テスト結論
- **スカートジョイントを外す(並進も自由)と 17,407→285(≈MMD67の桁)**。=**接触は本来解決できる。綱引きが真因**。
- **角度だけ自由ではほぼ効かない(11,651)→主犯は linear ロック**（スカートを下半身に位置固定し接触の押し出しを毎ステップ相殺）。
- ベースラインの実効回復は理論の**8%**＝押し出しの約92%がジョイントに打ち消される。求解順（各反復で接触→ジョイントの順、**ジョイントが後勝ち**）が効いている。
- **4点マニフォールドは不要**の裏付け: 点数を増やさずジョイントを外すだけで285まで落ちる＝点数不足が主因でない。

### (5) 検算・確認事項への回答
- **ShouldCollideゲート**: hairfidの17,407は**ゲート済み**（`if(!ShouldCollide)continue;`）。restsimの罠は踏んでいない。
- **8/07「F0〜120集中」との食い違い**: 今回は**駆動(MMDベイクCSVで脚が動く)・全7001フレーム・全ペア**での計測でユニークフレーム5746が全編に散る。
  8/07は**別シナリオ/範囲**（restsim=静止bind settlingの過渡、または単一ペア スカート_1_5×左太もも のみ）を見ていた可能性が高く、
  静止settlingなら初期に集中するのは自然。=測定範囲・シナリオの違いによるもので矛盾ではない（正確な当時スコープは要ログ確認）。

### (6) 修正の方向（診断を踏まえた候補・未着手）
- **接触の split-impulse**（貫入回復を擬似速度側へ）: 単体で 17407→5024。ジョイントの実速度解でキャンセルされにくい。
- **求解順/反復配分**: 接触に最後の一手を与える、または接触反復重み増。
- **MMDが同じhard lockで67で済む理由の追究**: MMDのsplit-impulse既定・反復数・substep等。SPLIT+反復増でMMDに近づくか要検証。
- ※linearロックを緩める方向は挙動が変わるため慎重に。

## 8. 【追記】補正ON/OFF/自前 3者比較（判定基準の再定義）

補正OFF版VMD(純Bullet)を入手し対照実験を実施。**判定基準を「Bullet忠実」→「MMD(補正ON)との距離」へ変更**。

- 駆動ボーン66本: ON/OFF **位置差0・回転差0**(入力同一)。物理ボーン101本のみ差=トグル有効。

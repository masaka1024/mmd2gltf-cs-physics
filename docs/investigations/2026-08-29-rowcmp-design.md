## 0. まず制約を確認する — 参照から「行」は取れない

PMXエディタは中身を観測できない (規約上も逆解析は禁止)。取れるのは **30fps のボーン姿勢だけ**。
したがって本タスクの「行レベル突合」は次の**二層構造**にする。混ぜないこと。

| 層 | 相手 | 取れるもの |
|---|---|---|
| **行レベル** | **当エンジン ↔ 素の Bullet 2.75 (`bulletref`)** | 行の本数・err・目標速度・力積・反復ごとの残差 |
| **結果レベル (裁定者)** | **真OFF 参照** | ボーン姿勢のみ。ここから**観測可能量**に落として3者を並べる |

★**参照を行レベルの相手にしてはいけない。** 参照に対して比べられるのは、
ボーン姿勢だけから計算できる量に限る。本書 §2 の `β̂` と `ē` はその条件を満たすよう定義する。

## 1. 対象行の選び方 — **全行が主。slip 上位は層別の従**

### 主: 全34関節 × 全ロック行

- この鎖は **全ジョイントが完全ロック** (位置/回転リミットもばねも全ゼロ) なので、
  6行すべてがロック行。並進3行・回転3行を**すべて**対象にする。
- 除外するのは次だけ: (a) アンカー関節 頭→`_0_1` (駆動が直接入るため引き戻しと励起を分離できない)
  → **別枠で報告**し主集計には入れない。 (b) 末端 `_33_1`→`_34_1` (剛体が無く縮退)。
  → **主集計 = 内部33関節。** タスク98 の slip 統計と同じ集合にそろえる。

### 従: slip 四分位による層別

**slip の大きい関節だけを選んで比べてはいけない。** 結果 (slip) で対象を選ぶと選択バイアスになり、
「硬い関節ほど硬い」という同語反復を測ることになる。層別は**報告の分解能**としてのみ使う:

- 参照 (真OFF) の窓内 slip 中央値で 34関節を **Q1..Q4** に分ける。層の定義は**参照側で決める**
  (当エンジン側で決めると、当エンジンの挙動で層が動いてしまう)。
- 各層で §2 の量を出す。**採否や結論は主集計 (全行) で決める。**

## 2. 突合する量 — 実効引き戻し率 `β̂` (実効ERP相当)

### 2-1. 違反量 `e` の定義 (3者すべてで同一・ボーン姿勢だけから計算できる)

関節 `j` の A側ボーン `a` / B側ボーン `b`、PMX 定義のジョイント位置 `J_bind`、
ボーンのバインド位置 `bind_a` / `bind_b` に対して:

```
pA(t) = pos_a(t) + rot(q_a(t), J_bind - bind_a)
pB(t) = pos_b(t) + rot(q_b(t), J_bind - bind_b)
e_lin(j,t) = | pA(t) - pB(t) |                       … 並進ロックの違反量 [units]
rel(t)     = q_a(t)^-1 * q_b(t)
rel_bind   = q_a(bind)^-1 * q_b(bind) = 恒等          … PMX のボーンは bind 回転を持たない
e_ang(j,t) = angle( rel(t) * rel_bind^-1 ) = angle( rel(t) )   … 回転ロックの違反量 [deg]
```

★**`e_ang` の基準は `rel(0)` ではなく bind (恒等) にする** (2026-08-29 差し戻しで変更)。
理由: **参照の f0 は鎖が11倍に伸びた過渡状態**であり、そこを原点に取ると
「違反ゼロの状態」ではなく「たまたま過渡の途中だった姿勢」を基準にしてしまう。
タスク98 d で f0 比較を廃止したのと同じ理由で、時間原点に依存しない bind を基準にする。

**旧定義との対応を1回だけ並べる。** タスク98 の slip 統計は `rel(0)` 基準で出ているので、
接続のために**同一窓で両定義の値を並記する欄を必ず設ける** (§5 の出力形を参照)。
以後の集計・判定は **bind 基準を主**とし、`rel(0)` 基準は対応表の1行としてのみ残す。
既存の `slip.py` / `three.py` は `rel(0)` 基準の実装なので、**bind 基準は別関数として足す**
(既存スクリプトの定義は書き換えない。物差しを黙って差し替えない)。

- バインドで `e_lin = 0`。移動ロックが守られていれば常に 0。**剛体オフセットは両側で相殺**するので不要。
- 仮定は1つ: **ボーンが剛体に剛に追従している (mode1)**。この鎖の剛体は全て mode=1 なので成立。
- `e_lin` は `lockdrift_onoff.py` の `d` と同一定義。`e_ang` はタスク98 の slip と同一定義。
  **既存の2つの物差しをそのまま流用する** (新しい物差しを作らない)。

### 2-2. 実効引き戻し率 `β̂` (per 1/30 秒)

参照は 30fps のサンプルしか無いので、**サンプル間の減り方**として定義する:

```
β̂(j,k) = 1 - |e(j,k+1)| / |e(j,k)|          （k は 30fps サンプル）
```

`β̂ = 1` なら1サンプルで違反を完全に消す。`β̂ = 0` なら消さない。負なら増えている。

**減衰区間だけを採る (励起との分離)。** 外から仕事が入っている最中の `e` は増えるので、
そのまま平均すると引き戻し率ではなく励起量を測ることになる。採用条件を事前に固定する:

- `|e(j,k)| >= e_min` … 分母が小さすぎるサンプルを除く。`e_min` は **参照の窓内 `|e|` の p50** とする
  (当エンジン側で決めない)。
- `|e(j,k+1)| < |e(j,k)|` … 減衰しているサンプルのみ。
- 上記を満たすサンプルが 1関節あたり **5個未満なら、その関節は集計から外す** (件数も必ず報告する)。

代表値は **関節ごとの中央値 → 関節間の中央値**。p90 も併記する
(NORTH_STAR の `|Δp|` と同じ集約規則にそろえる)。

★**注記 (バイアスの向き)**: 減衰サンプルだけを採ると `β̂` は上振れする。この上振れは
**励起が大きい側 = 参照側に強く効く** (参照は `e` が大きく、増減の混ざったサンプルが多いため、
減衰側だけを拾うと実際より引き戻しが強く見える)。つまり `β̂_ref` が過大に出る方向であり、
`β̂_eng / β̂_ref` は**過小評価**される。**したがってこのバイアスは H1 に対して保守的**
(H1 を通りにくくする側)。H1 が成立したなら、バイアスを差し引いても成立している。

### 2-3. ソルバ刻みの違いをどう扱うか — **ここを黙って潰さない**

`β̂` は「1/30 秒あたり」であって「ソルバ1ステップあたり」ではない。3者で刻みが違う:

| | 1/30 秒あたりのソルバステップ数 `N` |
|---|---|
| 参照 (PMXエディタ) | **2** (実効60Hz) |
| 当エンジン 既定 | **4** (60Hz × SubSteps 2) |
| `bulletref` | 起動引数で可変 |

同一 `β̂` でも `N` が違えば1ステップあたりの強さは違う。両方を出す:

```
β_step = 1 - (1 - β̂)^(1/N)
```

- **主比較は `β̂` (per 1/30 秒)** — これは「同じ時間で違反がどれだけ減るか」であり、
  出力一致を目的とする以上こちらが本命。
- **`β_step` は原因の所在を指すための補助**。`N` の違いで説明できる差なのかを判定する。
- ★**当エンジンを `N=2` にそろえた腕も回したい**が、それは **SubSteps を触る = 設定掃引**にあたる。
  **本設計に腕としては書くが、実行は別途の承認事項**とする (今回のタスクには含めない)。

### 2-4. 行レベル側 (当エンジン ↔ `bulletref`) で追加で取る量

こちらは中身が見えるので、`β̂` の**内訳**を取る。既存の `bulletref` 経路をそのまま使う
(`restosc NETDUMP=1` → `bulletref.exe --net ... --drive ...` → 行CSV)。

| 量 | なぜ見るか |
|---|---|
| 行の本数 (関節あたり・反復あたり) | 2026-08-22 に **自前13行 / Bullet 4行** の差が出ている。Bullet は `testLimitValue` が `test_value==lo` のとき行を作らない |
| `err` (行の違反量) | `e_lin` のソルバ内部版。外から見た `e` と一致するか |
| 目標速度 / **行構築時の相対速度** | 2026-08-22 の核心。静止では **相対速度/目標 = 自前 0.327 / Bullet 0.000409** だった。**駆動でも同じ構図かを確認する** |
| 力積 (絶対尺度) | NORTH_STAR §1-d: 静止では相対尺度を使わない。定常窓でも**参照側残差を尺度に取る** |
| 反復ごとの残差の落ち方 | `β̂` が反復回数で説明できるか |

★突合は **`NOCONTACT=1`** で行う (README_bulletref の理由。網に静的剛体が入っていないため)。
寄り添い部は OFF にする (NORTH_STAR 0節の運用)。

## 3. 番人 (新基準での成立確認) — 落ちたら数値を出さない

タスク98 d で改定した基準を、この突合の入口ゲートとして具体化する。
**窓 = 60Hz の f30..f50 (= VMD フレーム 15..25)。**

| # | ゲート | 条件 | 落ちたら |
|---|---|---|---|
| **G1** | 起動過渡を脱している | 参照 (真OFF) の窓内**全フレーム**でリンク長 max < **2.0x** | 窓を後ろへずらして再取得 |
| **G2** | 窓内が定常 | 窓を f30-40 / f40-50 に二分し、参照の slip 中央値の差が **20% 未満** | 窓長を延ばす |

| **1段目** | **f30..f50** | 15..25 | G5 除外が **5関節を超えたら** 2段目へ |

★**旧基準「f0 の位置差 0.02」は廃止済み。** 参照の f0 は鎖が11倍に伸びた過渡で、

## 4. 事前登録の判定基準

`β̂_ref` (真OFF) / `β̂_eng` (当エンジン) / `β̂_bul` (素の Bullet 2.75) と、
定常違反量 `ē` (窓内 `|e|` の中央) を出したうえで、**下表を機械的に当てる**。
表に無い結果が出たら「該当なし」と書き、読みを後付けしない。

| # | 条件 | 読み | 次にやること |
|---|---|---|---|
| **H1** | `β̂_eng` が `β̂_ref` の **2倍以上**、かつ `ē_eng << ē_ref` | **引き戻しが強すぎる。** 硬さの正体はロック行の引き戻し率 | 候補を **反復回数 / ERP / CFM相当の欠如 / 行数** へ絞る。`β_step` と行数で内訳を確認 |
| **H2** | `β̂_eng ≈ β̂_ref` (±20%) かつ `ē_eng << ē_ref` | **引き戻しは同等で、そもそも励起が入っていない。** 硬さではなく「揺すられていない」 | 候補を **励起側** (warm-start 0.85 / `SpringAsMotorRow` / 補正項の帰還 / 外力の伝わり方) へ |
| **H3** | `β̂_eng < β̂_ref` | 逆向き。引き戻しは硬さの説明にならない | 硬さの正体を**行数・行の作り方**へ寄せる (毎反復で行を作る等) |
| **H4** | `β̂_bul ≈ β̂_ref` かつ `β̂_eng` だけ外れる | **当エンジン固有**。素の Bullet は参照側 | 行レベル突合を続行。原則2 (出力が勝つ) の対象 |
| **H5** | `β̂_bul ≈ β̂_eng` で、2つとも `β̂_ref` から外れる | **Bullet と PMXエディタの差**。当エンジン固有ではない | NORTH_STAR 原則3 の判定へ (参照が人工物か) を先に決める |
| **H6** | 番人 G1-G6 のいずれかが落ちる / G5 で標本不足 | **判定不能** | 数値を出さない。窓か参照を作り直す |

### 事前に立っている仮説 (外れても書き換えない)

2026-08-22 の静止での実測 —— 並進ロック行の **行構築時の相対速度 / 目標速度** が
**自前 0.327 / Bullet 0.000409** —— は、**H1 を予測する**。
「err を速度に変えるかどうか」の差がそのまま引き戻し率の差になっているなら、
駆動の定常窓でも `β̂_eng > β̂_ref` が出るはず。**この予測が外れたら、静止での結論の
適用範囲が狭かったということであり、H2/H3 の側へ素直に移る。**

### 判定の境界を先に決めておく理由

「2倍以上」「±20%」は**後から動かさない**。動かすと、どんな結果でも好きな読みに割り当てられる。
値そのものは目安だが、**先に書いてあること**に意味がある。

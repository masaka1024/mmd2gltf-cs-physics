インポーター側 (`<importer リポジトリ>`) から PhysX 経路を撤去し、物理を本エンジンへ
一本化した直後、**手元の他モデルを再生した途端に不具合が 4 件連続で露見**した。

## 1. 陽的ばねの発散 (NaN)

**症状**: モデルC を再生すると直後に
`transform.position ... is { NaN, NaN, NaN }` が大量発生してスケルトンが壊れる。

**真因**: `Joint.ApplySprings` が陽的 (前進オイラー) `impulse = -k*err*dt` で、安定条件
`k·dt²/m < 1` を担保していなかった。1 ステップの速度変化が `k·err·dt/m` になるため、
誤差が毎ステップ `k·dt²/m` 倍に増幅される。

同モデルは `spring = 100000` に対しツインテール先端の錘 (ボーンなし剛体) の質量が 0.01 で
`k·dt²/m = 2778`。実測で毎ステップ約 30 倍に発散し、25 ステップで float が溢れた。

```
step  1: |v|max=7.0        step  8: |v|max=1.4e10
step  2: |v|max=187        step 20: |v|max=5.1e20
step  3: |v|max=5844       step 24: |v|max=3.9e35   ← float 上限
step  4: |v|max=1.4e4      step 25: NaN 80体
```

**切り分けの決め手**: **重力をゼロにしても同じように発散した**。外力ではなくばね自身が
エネルギー源だと確定できた。

**対策**: 力積を `|err| · mEff / dt`（デッドビート = `k·dt²/m` が 1 に相当する安定限界）で
頭打ちにする。`mEff` は `AddLinearRow` / `AddAngularRow` と同一式なので、健全な範囲では
1 ビットも変わらない。A/B (300step 全剛体姿勢ハッシュ) で モデルA 系 3 モデルはビット完全一致を確認。

**モデルA が見逃した理由**: 全ジョイントの**ばね定数が 0**。`ApplySprings` が早期 return するため
一度も通っていなかった。

## 2. PMX オイラー角の順序 (ZYX → YXZ)

**症状**: 髪のコライダーが髪の流れに沿わない（複合回転の強いツインテールで顕著）。

**真因**: `Quat.FromEuler` が `Rz·Ry·Rx` (ZYX) だったが、PMX の剛体/Joint 回転は
`Ry·Rx·Rz` (YXZ、Bullet の `btQuaternion(yaw,pitch,roll)` と同型)。
`RigidTransform.FromEuler` 経由で剛体 `WorldTransform` / `ComputeOffset` / Joint `worldFrame` の
3 箇所すべてに効いていた。

**検定法 (再利用可)**: **カプセル剛体のローカル Y 軸と「ボーン→子ボーン」方向のズレ角**を
オイラー 6 順序で総当たりする。髪カプセル 402 本の合計で 中央値 2.3° → **0.0°**、
15° 以内 90.0% → 91.5%。モデル別 (髪のみ) は 10 改善 / 2 同等 / 悪化ゼロ。

> 体の剛体 (胸・腰) は本来カプセルが直交するので、全剛体で測ると指標が濁る。**髪に絞ること**。

**傍証**: 撤去した旧 PhysX インポーターは `Quaternion.Euler`（= Unity の YXZ）を使っており、
当時のコライダーは流れに沿っていた。エンジン移植時に順序が入れ替わったことになる。
**「旧実装では正しかった」は強い手掛かりになる。**

**モデルA が見逃した理由**: 複合回転が小さく、ズレが 1.1° に留まっていた（モデルCは 5.8°）。

## 3. 物理の書き戻しタイミング (FixedUpdate → LateUpdate)

**症状**: モデルE。バインド姿勢は正常なのに、アニメを再生すると
**1 フレーム目から**スカートが開いたまま固定される。

**真因**: `PullPhysicsToBones()` を `FixedUpdate` で呼んでいた。Unity のフレームは
`FixedUpdate → Update → [Animator適用] → LateUpdate` の順なので、揺れ物ボーンにカーブを持つ
クリップでは物理の書き戻しが毎フレーム Animator に潰される（レストポーズの定数キーでも同じ）。

実測でモデルEのスカートはレスト時の水平半径 2.09 に対し物理で落ち着くと 1.93。
「開いたまま」= レストポーズそのものだった。

**切り分けの決め手**: 「**1 フレーム目から**」という一語。蓄積 (遠心力) ではなく**上書き**だと
確定した。それ以前に「アニメ中に広がる」と理解して合成モーション (全身旋回 360°/s、
脚振り ±50°) で 3 回試したが、いずれも再現しなかった。
→ **症状の時間発展 (徐々に / 即座に、戻る / 戻らない) を最初に確認すべき。**

**副次効果**: モデルCの**マントの暴れも同時に解消**した。書き戻しが「描画フレーム
ごとに正確に 1 回」になったため。`FixedUpdate` は 1 描画フレームに 0/1/2 回と揺らぐので、
以前は反映タイミングが不均一 = 時間的エイリアシングだった。
→ **揺れ物の "暴れ/カクつき" を見たら、物理パラメータより先に書き戻しタイミングを疑う。**

**モデルA が見逃した理由**: 本体のみベイクで**揺れ物カーブが無い**ため、Animator が揺れ物ボーンに
触らず競合しなかった。

## 4. PMX mode2 (物理演算 + ボーン位置合わせ) の未実装

**症状**: モデルB のスカートがMMDより柔らかい。

**真因**: `PhysicsMode.DynamicBoneMerge` が列挙子だけで、エンジン内の判定が全て
`!= BoneFollow`。mode1 と同一の「完全自由」として扱っていた。

**★実装方式を一度誤った**。「物理ステップ直前に剛体位置を固定し並進速度をゼロにする」と
解釈してシミュレーションを拘束したところ、旋回時に遠心力を担う並進速度まで消え、
**髪が回転軸へ collapse** した（モデルB 旋回 360°/s の髪: 振幅 1.156 → 2.185、最小半径 2.73 → 1.70。
同モデルは髪 26 剛体中 24 が mode2）。

正しくは mode2 は**書き戻し側**の仕様で、「位置は親チェーン由来 / 回転は物理」を**出力**する
だけ。シミュレーションには触れない。

> **答えは既存コードのコメントに書いてあった。** `ComputeAlignedBonePoses` に
> 「PmxEditorの補正層再現」「物理ボーンの**出力姿勢**」と明記されており、これがまさに
> mode2 の計算だった。`AlignBonePositions` という全剛体一律のトグルに繋がれていただけ。
> **新規実装の前に、既存に同じ計算が無いかコメントごと読むこと。**

**効果**: 出力ボーン位置ベースの計測ではスカートの振幅 0.185 → 0.175（5%）と小さいが、
**実機の見た目の改善は大きい**（ユーザー確認「いまいちだったものが問題なしになった」）。
振幅は「揺れの大きさ」しか測っておらず、mode2 が実際に直す「各段が並進でズレて**シルエットが
崩れる**」= 形状の一貫性を捉えられていなかった。
→ **揺れ物の品質は振幅だけでなく形状の指標も併せて見ること。**

**モデルA が見逃した理由**: mode2 の剛体が **0 個**。

## 教訓

1. **1 モデルで詰めた品質は、他モデルでの正しさを保証しない。** 新しい修正は、ばね定数・
   mode2・複合回転・揺れ物カーブを持つ別モデルでも必ず回す。所持モデルの特性表は
   `scratchpad` の診断スクリプト (`diag_glb.py` / `axischeck.py`) で即座に出せる。
2. **症状の時間発展を最初に聞く。** 「徐々に / 1 フレーム目から」「戻る / 戻らない」で
   原因の種類（蓄積か上書きか）が決まる。
3. **自分の直近の変更をまず疑う。** 「モデルBが柔らかい」の調査では、最初に自作のばねクランプを
   A/B した。結果クランプを外すと モデルBは発散し (半径 1.77 → 7.8)、クランプは原因ではなく
   必須だと分かった。
4. **既存コードのコメントを読む。** mode2 は既に実装されていた。
5. **提案する検証手順は、実装を読んでから出す。** `AlignBonePositions` を ON にして確認、と
   提案したが、あれは書き戻し表示を変えるだけでシミュレーションを拘束しないため、
   ユーザーの「変化無し」は情報量ゼロの結果になり無駄足を踏ませた。

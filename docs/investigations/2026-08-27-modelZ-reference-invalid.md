# モデルZ 参照の全期間無効化と、原因究明スレッドの終了 (2026-08-27 タスク84)

> ★このファイルは会話中「fume-miku-issue.md」と呼ばれていたもの。
> 追跡ファイルに実モデル名を残さない規約 (model-alias-map) に従い、別名で置いている。
> モデル別名の対応は非追跡の NAMES.local.txt を参照。

## 締め

**モデルZ の参照は、タスク79〜83 の全期間を通じて一度も健全でなかった。**

1. **名前潰れによる捏造** (〜タスク82 で発覚): VMD のボーン名は 15バイト shift_jis 固定。
   このモデルの物理ボーンは中国語名なので、ベイク時に `?` へ潰れて保存される。
   glb 名で完全一致検索していたため一致 0本、補間関数が恒等を返し、
   **鎖が「剛体の棒」として組み上がった参照**が出来ていた。
2. **修正版も不合格** (タスク83①): 潰れ規約を合わせて再生成したが、
   ・f0 で当エンジンと **位置差 中央 15.02 units / 角度差 中央 92.8°**
   ・`samp()` がゼロ次ホールド (30fps キーを 60fps へ据え置き) で **2フレーム周期の階段**
   ・VMD 鎖トラックが 1/30秒で 159°→44°→12° と非物理的に振れ、回転角の中央値が 0.00°
   VMD→glb の四元数規約 `(-x,-y,z,w)` 自体は駆動ボーン5本で残差 0.000° と独立検証済みなので、
   規約の誤りではない。**f0 の 92.8° と非物理的な振れの原因は未解明。**

→ **原因究明スレッド (タスク79〜83) は、健全な比較対象を一度も持てないまま終了する。**
   **実機で観測された揺れ物の破綻の物理的な原因は未解明のまま棚上げ。**

## 撤回する数値結論 (消さずに撤回記録として残す)

いずれもモデルZ 参照 (捏造版または不合格の修正版) に依存しており **無効**:

- 「ロック行 (角度・lo==hi) が f778 以降保持できず鎖が抜ける」等、タスク80/81 の診断一式
- 減衰クランプ 1.0 の「3〜26倍改善」と区間別の改善倍率
- SubSteps 掃引値 (2/4/6/8 の定常・スパイク値すべて)
- ERP 0.2 vs 0.5 の掃引値 (モデルZ・モデルA 双方)
- モデルZ の全 posRMS / 角度値 (f700 の 0.334/1.87°、f784 再現値 4.465/36.15° 等)
- 質量クランプ 1e3 の「忠実度 19倍/15倍を代償」と「撤去条件 = 定常 2.2° 維持」

## 撤回しないもの (モデルZ 参照に依存していない)

- `LockedRowImpulseBound` のシロ判定。根拠は **A/B 出力ハッシュ**であって参照突合ではない
  (1e17〜3e38 でビット一致、1e16 で初めて動く → 実インパルスの最大は 1e16〜1e17)。
  Bullet 実ソース (`btGeneric6DofConstraint.cpp:827-842` の `SIMD_INFINITY` = `FLT_MAX`) に基づき
  既定を `float.MaxValue` にした件も**維持**。3複製ビット不変を確認済み。乖離一覧からは削除のまま。
- 「極端値を前提にした最適化 5箇所は無害」(同じく A/B ビット不変ベース)
- **ERP 0.2 に採用理由の記録が無いという事実** (コード考古学の結果、参照非依存)。
  ただし 0.5 との優劣は **未決に戻す**。→ 乖離一覧に1件残す。
- 診断足場そのもの (SyncGuard / `DampingClampMax` の外出し / `cmpref` / `three.py` / `refgen`)。
  いずれも既定でビット不変。

## ★測定 artifact が診断を無効化した事例 — 本スレッドで **4回**

| # | artifact | 何を壊したか |
|---|---|---|
| 1 | **MASSKIN** | 巨大質量のキネマ化が剛体をバインド姿勢に釘付けし、下流ごと凍結。`\|v\|` ゲートが鳴らないのを「完治」と誤読 |
| 2 | **f784 の集計法** | RMS か最大かを記録しておらず、同条件で 3.34 と 4.465 が食い違った |
| 3 | **参照の名前潰れ捏造** | 一致 0本で鎖が「剛体の棒」に。タスク79〜81 の診断を丸ごと無効化 |
| 4 | **ゼロ次ホールド** | 30fps キーを 60fps へ据え置き。修正版参照にも階段が残った |

**共通する唯一の兆候は「結果が不自然にきれい / 都合が良い」だったこと。**
対策として、参照を作る側と使う側の両方に停止ゲートを入れた:

- `tools/diagnostics/divhunt/refgen.py` — トラック一致本数が不足したら参照を書かずに `exit 2`
- `tools/diagnostics/divhunt/cmpref.py` (v1.2) — ゲートB (鎖に独立運動が無い) で **数値を出さずに FAIL**
  ・ゲートA (隣接名ボーンの距離変動) は実装者自身が誤設計と判定して**警告に降格**。
    物理ベイクはボーンに並進も焼き込むので親子距離は不変ではなく、
    検証済みの別モデル参照で誤検知した。その経緯はコード内コメントに残してある。

**これらは「2026-08-27 に実際に起きた捏造をまさに検出する仕組み」である。削除禁止。**

## 実機の実害

**未対処のまま。** 揺れ物の破綻は実機で観測されている。`SubSteps` を上げれば緩和できる
見込みはあるが、**その定量的な根拠は上記の撤回で無効化された**。
要否と度合いは **実機の目視でのみ判断すること**。
`SceneMaxDynamicMass` / `SubSteps` のシーンへの適用は、根拠が無いので**行っていない**。

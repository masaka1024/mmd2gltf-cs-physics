# pmxeprobe — PmxEditor 補正層のブラックボックス同定

PmxEditor の物理設定にある **[ボーン位置合わせ再計算]** と **[Jointロック内部演算]** が何をしているかを、
最小 PMX を食わせて出力を測ることで同定する。

## 前提: 規約

PmxEditor の `readme.txt` §禁止事項に「ソフトウェアのリバースエンジニアリング及び不正な解析行為」
「リバースエンジニアリング及び不正な解析行為等で得た情報の公開、取得」が明記されている。
本ツールは**逆コンパイルもバイナリ解析も行わない**。使うのは

1. 同梱ドキュメント (`Lib/PMX仕様/PMX仕様.txt`, `readme.txt`)
2. 入出力のブラックボックス実験（＝ソフトウェアの通常利用）

の2つだけ。

## 設計方針

**軌跡ではなく静的平衡（固定点）を測る。** 実モデルで補正 ON/OFF を比べると別ベイクで軌道が分岐し、
フレーム単位の対応が取れない。1リンク・接触なし・減衰ありの系にすれば収束先が決定的になり、
入出力対応が一意に取れる。

- 非衝突グループフラグ `0x0000` … どの剛体とも衝突しない。残る力は重力と Joint のみ
- ばね0・反発0・摩擦0 … 未知パラメータを消す
- 球形状 … カプセルのマージン挙動（2.75 と 2.8x で差がある箇所）を回避
- リンク1本 … PGS の鎖漏れが構造的に起きない

## スクリプト

| | |
|---|---|
| `make_probe_pmx.py` | PMX 2.0 を直に書き出す生成器。`models/` へ出力 |
| `validate_probe.py` | 生成器とコードを共有しない独立リーダで検証。全セクション消費＋EOF一致 |
| `compare_probe.py` | PmxEditor の結果 PMX を読み、傾き/リミット超過/ロック違反/ボーン傾きを比較 |
| `triad_probe.py` | 測定用四面体から、メッシュに実際に効いた変換行列を復元（回転側の観測） |
| `multi_probe.py` | 複合プローブ（1モデルに独立実験を並べたもの）を島ごとに集計 |
| `make_probe_vmd.py` | 島の親ボーンを揺さぶる VMD を生成（動かさないと出ない挙動を捕まえる用） |
| `compare_vmd.py` | Fix ベイクした VMD を2本、全フレーム比較 |

```bash
python make_probe_pmx.py
python validate_probe.py
python compare_probe.py models/E2_lim5_m1.pmx out/E2_m1_g98_A*.pmx
```

## GUI 往復を減らす2つの仕掛け

**1. 1モデルに実験を並べる（`E9_multi.pmx`）**
剛体マスク 0x0000 で島どうしは干渉しないので、独立した振り子を何個並べても各島が勝手に
自分の固定点へ落ちる。トグル条件だけは分離が必要だが、それ以外（鎖の長さ・Joint オフセット・
腕の長さ・リミット角・剛体モード・移動ロック有無）は全部同居できる。
質量非依存が分かっているので、荷重を振りたいときはリンク長を変えればよく、重力を触らずに済む。
→ 44回ぶんの撮影が 2〜3回になる。

**2. Fix ベイク（これが本命）**
[編集]-[Fix再構築] で物理込みのモーションを確定し、[Fixモーションの非物理化保存] で
1F毎に全キーの入った VMD へ落とせる（`readme.txt:4022`, `4037`）。
静止を待つ必要が消え、**軌跡ごと比較できる**ので「過渡にだけ効く挙動」も捕まえられる。
手順: モデルを開く → VMD を TransformView へ D&D → トグル設定 → 物理 ON →
[Fix再構築] → [Fixモーションの非物理化保存]。

## 計測手順（GUI）

1. `models/*.pmx` を PmxEditor で開く（**毎回開き直す**。前回の状態を持ち越さない）
2. 変形画面 → [物理演算設定] でトグルと重力を設定
3. 物理演算 ON（稼働中なら [物] 2度押しで初期化）→ 1秒ほどで静止
4. **物理 ON のまま** [ファイル]-[現在の形状で保存] → `out/` へ

### 落とし穴

- **VPD は使えない。** `readme.txt:3769`「vpd:変形分のみ」で物理の結果は記録されない（実測で bone count 0 の空ファイル）
- **保存前に物理を OFF にしない。** `readme.txt:3706` のとおり ON/OFF 切り替えで状態が初期化される
- **表示枠は Root と 表情 の2つが必要。** Root だけだと保存が通らない
- **重力の既定は 9.81 × 10 = 実効 98.1。** 物理設定に倍率欄がある
- **ボーンに移動可能フラグ(0x0004)が要る。** 無いと [Fixモーションの非物理化保存] が
  「保存に失敗しました」で落ちる（物理で動いたボーンは平行移動しているので移動キーが必要）
- **収束確認を先に、条件比較は後。** 同条件で2回撮ってゆらぎがゼロの島だけを判定に使う。
  腕が長い島・リミットが広い島・3リンク鎖は固定点に落ちない（`len4` / `lim30` / `chain3`）
- **四元数の比較に `2*acos(|dot|)` を使わない。** ほぼ一致する四元数で条件数が最悪になり、
  float32 の丸めだけで 0.026° の偽の差が出る。実際これに騙されかけた。相対四元数の atan2 を使う

## 結果ファイルの命名

```
<実験>_<質量>_<実効重力>_<トグル>.pmx
   例: E2_m1_g98_A1B0.pmx = E2, 質量1, 実効重力98.1, A=ON, B=OFF
```

`A` = [ボーン位置合わせ再計算]、`B` = [Jointロック内部演算]。`E6` は重力計なのでトグル無し。

`models/` は追跡していない（`make_probe_pmx.py` で決定的に再生成できるため）。`out/` は GUI 操作でしか
得られないので追跡する（リポジトリ直下の `*.pmx` 除外を `out/.gitignore` で打ち消している）。

出自の注記:
- `E2_m1_g98_A*` の4本は表示枠に「表情」を足す前のモデルで取得したもの。md5 は他と揃わないが測定値は一致。
- `E2_m1_g98_*_2nd` の2本は当初 `g981` として保存したが、重力変更が反映されておらず実際は既定重力だった
  （下記「訂正の経緯」）。現行モデルで撮った E2 の測定として有効なので改名して残している。
- `witness.pmx` は重力が既定に戻っているかの確認用。ロック違反が `0.186393` なら正常。

## 判明していること

### [ボーン位置合わせ再計算] = 剛体モード2 の「移動分を捨てる」処理

E4（子剛体 mode2、回転リミット±5°）で結果が2種類に割れた。

| A | 子ボーン位置 | 子剛体位置 |
|---|---|---|
| ON | **(0,10,-2) = bind から動かない** | (0, 9.640016, -1.976020) |
| OFF | (0, 9.640016, -1.976020) = 剛体と同一 | 同左 |

`readme.txt:970`「(PMXでは)移動分を捨てて回転のみをボーン側へフィードバック」が float 精度で確認できた。
**mode1 剛体には A は効かない**（E2 の4条件が一致する理由）。

### 平衡は重力に正比例、質量には非依存

E2 の静的平衡（実効重力 98.1）は `傾き +10.3247° / ロック違反 0.186393 / 剛体回転 -5.0000°`。

- **質量 1→10 で不変。** 重力は加速度なので駆動トルクも慣性も質量に比例し、違反量は質量に依らない。
  実効質量のスケーリングが正しいことの裏返しでもある。
- **重力 10倍でロック違反も約10倍**（0.186393 → 1.79〜1.86）。ERP/Baumgarte の定常誤差そのもの。

**訂正の経緯**: 一時「荷重100倍でも1ビットも動かない」と記録していたが、これは誤り。
`E2_m1_g981_*` として保存した2本に重力変更が反映されておらず、実際は既定重力のままだった。
その後 E7/E8 を誤って10倍重力のまま撮影したことで 約10倍の違反量が出て発覚した。
`frame offset が犯人` という筋読みも同時に取り下げ。

**再発防止**: 重力を変えた回は、毎回 `E2_lim5_m1.pmx` を1本回して
ロック違反が既定値 `0.186393` に戻ることを確認してから本番を撮る（`out/witness.pmx`）。
上記の10倍データは撮り直しで上書きされ現存しない。荷重応答曲線が要るなら意図的に撮り直すこと。

### ★[ボーン位置合わせ再計算] は回転を一切いじらない

測定用四面体（E7=mode1 / E8=mode2）で、メッシュに実際に効いた変換を復元した結果:

| | 回転X | O の移動量 | 軸長 | 直交性 |
|---|---|---|---|---|
| E7 mode1 A=ON / A=OFF | -5.0000° | 0.360782（一致） | 1.00000 | 4.65e-07 |
| E8 mode2 A=OFF | -5.0000° | 0.360782 | 1.00000 | 4.65e-07 |
| **E8 mode2 A=ON** | **-5.0000°** | **0.000000** | 1.00000 | 4.65e-07 |

O の移動量 0.360782 は剛体が (0,10,-2) → (0, 9.640016, -1.976020) へ動いた距離と一致する。
= **平行移動成分だけを捨て、回転は無加工で素通しする**。スケールも剪断も入らない（軸長1.0・直交性ほぼ0）。
mode1 では A の ON/OFF に差が出ない。

### 回転は厳密、位置が破れる

回転リミットの超過はゼロ（-5.0000° で厳密クランプ）だが、移動ロックは 0.186 破れる（腕長の 9%）。
接触もチェーンも無い1リンク静止系なので、鎖漏れでも綱引きでもなく移動ロック行そのものの性質。

### [Jointロック内部演算] は全域で無効

ON / OFF で **Fix ベイクした VMD が byte 完全一致**（9676キーを成分比較して差 0.000e+00）。

検証した空間:

| 軸 | 範囲 |
|---|---|
| 時間 | 601フレーム全部（揺さぶり＋再収束の軌跡ごと） |
| 鎖の長さ | 1 / 2 / 3 リンク（動的×動的の移動ロックを含む） |
| Joint オフセット | 親 / 中点 / 子 |
| 腕の長さ | 0.5 / 1 / 2 / 4 |
| 回転リミット | 0° / 5° / 30° |
| 剛体モード | mode1 / mode2 |
| 移動ロック | あり / なし |
| 質量・重力 | 1 / 10、98.1 / 981 |

`readme.txt:1051`「移動ロック指定のJointは内部的に補正処理を行っています」という記述はあるが、
変形画面の物理挙動としては観測できない。残る可能性は VMDView 側など別経路だが、
**再実装の対象としては no-op** と結論してよい。

途中「B が発動した」と誤読しかけたが、同条件の再撮で同じ島が同じだけ動いたため未収束と判明。
条件差を見る前に必ずノイズ床を測ること。

### 計測系の検証

重力計 `E6`（ばね k=100、m=1）でたわみを測定:

| 重力加速度欄 | たわみ | 逆算 g = k·x/m |
|---|---|---|
| 9.81（実効 98.1） | 0.944066 | 94.41 |
| 98.1（実効 981） | 9.440659 | 944.07 |

比は **10.0000**。重力ノブは正しく機能している（公称比 96.2% はばねの離散化ぶん）。

### 他エンジンとの比較用の基準値

接触もチェーンも交絡も無い16構成での PmxEditor の値。自作エンジンの線形ロックを評価する物差しになる。

| 構成 | 拘束違反 | 回転 |
|---|---|---|
| 単リンク・Joint は親位置 | 0.186393 | -5.0000°（リミット厳密、超過ゼロ） |
| 同・Joint は中点 | 0.03267 | -5.0000° |
| 同・Joint は子位置 | 0.00000 | 0° |
| 2リンク鎖 (link 1.0) | 0.13528 / 0.05883 | -5.00° / -12.87° |
| 2リンク鎖 (link 0.5) | 0.02557 / 0.01669 | -5.00° / -11.23° |
| 移動ロックなし（対照） | 5.18568 | -5.0000° |

## 残っている課題

- **自作エンジンに同じプローブを食わせる**（`MMD_TEST_PMX` で `E9_multi.pmx` を渡す）。
  GUI 不要で、上の基準値と直接比較できる。線形ロックが「純Bullet より緩い」という
  以前からの疑いを、交絡ゼロの16構成で判定できる。
- 3リンク鎖・腕4・リミット30° は固定点に落ちない。軌跡で比べるなら Fix ベイクを使う。

# bulletref — 本物の Bullet 2.75 と当エンジンを、同じ最小網で行レベルに突き合わせる

タスク20。タスク15 で確定した最小網 (Joint 5本 / 剛体6個 = 1房の鎖4本 + 横渡し1本 + アンカーの頭) を
**数値のまま** 取り出し、本物の Bullet 2.75 で組み直して並べる。

`bullet-2.75/src` は **1行も改変していない**。行レベルの観測は `btDiscreteDynamicsWorld` を継承して
`solveConstraints()` を override し、ソルバ自身が `getInfo1`/`getInfo2` を呼ぶのと同じ地点で
同じ呼び出しをしている (同じ状態に対して決定的なので、ここで出る値はソルバが使う値そのもの)。

---

## 構成

| ファイル | 役割 |
|---|---|
| `build.bat` | Bullet 2.75 コア (LinearMath + BulletCollision + BulletDynamics, 113ファイル) と `bulletref.exe` をビルド |
| `bulletref.cpp` | net.txt を読んで Bullet 2.75 の世界を組み、回して CSV を吐く |
| `compare.py` | 3段階の突き合わせ (初期一致 / 1サブステップ目の行 / 定常errの分岐点) |
| `sweep.py` | 当エンジンの各フラグ × Bullet の各 ERP を一括で回して表にする |
| `../restosc/NetDump.cs` | 当エンジン側のエクスポータ (`restosc NETDUMP=1`) |

### ビルド上の注意 (踏んだ罠)
- **cmake は使えない。** 2.75 の `CMakeLists.txt` は `cmake_minimum_required(2.4)` で、現行 cmake が拒否する。
  必要なのはコア3ライブラリだけなので `cl.exe` へ直接渡している。
- **`.bat` は ASCII のみで書く。** cmd.exe は OEM コードページ (ここでは CP932) で読むので、
  UTF-8 の日本語コメントを入れるとパーサが壊れる。日本語の注記はこのファイルに置く。
- **`cl` の応答ファイルに引用符を付けてはいけない。** `@"path"` は `D8003 ソースファイル名がありません`
  になる。`@path` と書く (113ファイルで 8191文字を超えるので応答ファイル自体は必須)。

## 使い方

```bash
# 1) Bullet 2.75 コア + bulletref をビルド (初回のみ。2回目以降は exeonly)
cmd /c build.bat
cmd /c build.bat exeonly

# 2) 当エンジンから最小網を書き出す (★突き合わせは NOCONTACT=1 で行うこと。理由は下記)
cd ../restosc
MMD_TEST_PMX=$MMD_TEST_PMX \
NETDUMP=1 FRAMES=600 SUBSTEPS=2 ITERS=10 NOCONTACT=1 \
OUTDIR=../bulletref/final dotnet run -c Release

# 3) 同じ網を Bullet 2.75 で回す
cd ../bulletref
./bulletref.exe --net final/net.txt --frames 600 --substeps 2 --iters 10 --out final --nocontact

# 4) 突き合わせ
python compare.py --dir final

# 5) フラグ総当たり
python sweep.py --frames 600
```

### ★NOCONTACT が要る理由
既定のまま最小網を組むと、生かした髪剛体が **体側の静的剛体** (下半身 / 左右太もも / 左ひざ) と
接触する (600F で 2126 点)。`net.txt` にはその静的剛体が入っていないので、そのままだと
「ジョイントの差」を見ているつもりで接触の有無を見てしまう。両側で接触を消してから比べること。
※ 接触を消しても結論は変わらなかった (下表)。接触は原因ではない。

## 結果 (2026-08-22)

### 段階1: 初期一致 = ★完全に一致

慣性テンソルは当エンジンの値をそのまま `setMassProps` しているが、Bullet 自身の
`calculateLocalInertia` と比べても **比 1.000** (float の丸めのみ)。
ジョイントのアンカー間距離は 0〜2.4e-7、初期 err も 0〜2.4e-7。
**網は数値レベルで完全に移植できている。**

### 段階2: 1サブステップ目の行

err はどちらも 1e-14 以下で一致 (差の最大 2.1e-14)。
唯一の差は **行の本数**: 自前 13行 / Bullet 4行。
Bullet の `btTranslationalLimitMotor::testLimitValue` は、ロック軸 (lo==hi) でも
`test_value` がちょうど lo のときは `m_currentLimit=0` を返して **行を作らない**。
当エンジンはロック軸なら err=0 でも必ず行を作る。
→ frame 0 限定の差 (次のサブステップ以降は err≠0 になり両者とも行を作る)。

### 段階3: ★★定常での分岐 = 110倍

### 正体: 抽出する行列が転置している

外部の独立計算 (numpy) で `XYZオイラー(R_A⁻¹R_B)` と `XYZオイラー(R_B⁻¹R_A)` を出したところ、

- **`XYZオイラー(R_A⁻¹R_B)` = 当エンジンの値 (15 DOF すべて 7桁一致)**
- **`XYZオイラー(R_B⁻¹R_A)` = Bullet の値 (15 DOF すべて 7桁一致)**

抽出式そのものは両者同一である
(`y=asin(m02) / x=atan2(-m12,m22) / z=atan2(-m01,m00)`)。
Bullet も `calculateAngleInfo` で `relative_frame = A.basis().inverse() * B.basis()` = R_A⁻¹R_B を渡している。
にもかかわらず結果が転置になるのは、**要素アクセスが列優先だから**:

```cpp
// btGeneric6DofConstraint.cpp:57-62  (Bullet 2.75 原文ママ)
btScalar btGetMatrixElem(const btMatrix3x3& mat, int index)
{
    int i = index%3;
    int j = index/3;
    return mat[i][j];      // ← index=2 は mat[2][0] = m20。m02 ではない
}
```
`btMatrix3x3` は行優先なので、`matrixToEulerXYZ` は**渡された行列の転置**に対して働く。
転置 = 逆回転なので `XYZオイラー(R_B⁻¹R_A)` になる。

**★これは「単なる符号反転」ではない。** 逆回転の XYZ オイラーは元の負値と一致しないので、
**大きさそのものが変わる** (0.3894 vs 0.2950 / 1.0654 vs 1.0510 / 0.2474 vs 0.2490 …)。
その結果 **どのリミットを超えるかが変わる**。

# タスク22: Bullet 角度規約の A/B 実装と段階検証 (2026-08-22)

## 1. 実装: `Joint.BulletAngleConvention` (既定 false = ビット不変)

2点セットで初めて意味を持つ:
1. `cur = XYZオイラー(R_B⁻¹ R_A)` — Bullet の `btGetMatrixElem` が列優先添字で
   `matrixToEulerXYZ` が転置に対して働くため (タスク21 §59)
2. **角度行の軸を反転** — cur の時間微分が `(wA-wB)·axis` になるので、相対速度を
   `(wB-wA)·axis` で測る当エンジンの行と符号を合わせる。これで err の作り方・
   不等式の側・力積の上下限が Bullet と1対1に対応する
